## Backend pipeline (current shape)

Cala's data flows in one direction — event/period text only — through five scripts plus one shared module:

- **`backend/knowledge_search.py`** — calls Cala MCP `knowledge_search` (JSON-RPC over HTTP, `CALA_API_KEY`) for a free-text query, extracts `title`/`fact`/`description`/`timeline` per result via the explainability→context→origins provenance chain. Writes `data/knowledge-search.json`.
- **`backend/knowledge_search_events.py`** — same Cala call, but with `return_entities: True`; produces `event`/`timeline`/`title`/`source_url`/`entities` (Cala's own typed entities matched to the event text), sorted chronologically. Writes `data/knowledge-search-spain-2.json`. This is the closest existing precedent for pulling structured entities (people/places) out of Cala — it already resolves `entities: [{name, entity_type}]` per event but never persists or displays them beyond attaching them to events.
- **`backend/main.py`** — standalone/older path: reads a knowledge-search JSON, calls OpenAI (`gpt-4o-mini`, Responses API) to build an image prompt per result, then Fal (`fal-ai/flux/schnell`) to generate + download an image. Writes back into the same input JSON plus JPEGs under `data/photos/&lt;slug&gt;/`.
- **`backend/generate_photos.py`** — similar but skips OpenAI; builds prompts directly from `fact`/`timeline`, calls Fal, writes to `data/ohotos/` (sic) and a `prompts.json`.
- **`backend/story_pipeline.py`** — shared, no-API pure logic module: normalizes Cala records, builds the OpenAI curator prompt/schema (6-moment story), validates GPT output against source indices, builds the frontend story JSON shape, builds Fal prompts, and appends to `data/fal.json` (credential-scrubbed run log).
- **`backend/generate_story.py`** — the current main pipeline (per README): reads a Cala knowledge-search JSON → `normalize_cala_records` → OpenAI (`gpt-5` by default) curates a 6-event chronological story with strict JSON schema → Fal (`generation_model` then `edit_model`, e.g. FLUX.2 Pro + Pro Edit) generates and style-anchors one image per event → writes `frontend/data/esp.json` + JPEGs in `frontend/public/moments/esp/` + appends to `data/fal.json`. Has a separate anchor-approval flow (`--create-anchor-candidates` / `--select-anchor`) gated on `data/styles/museum-editorial-v1.json`.
- **`backend/generate_nano_banana_trial.py`** — one-off trial script reusing `generate_story`/`story_pipeline` helpers to call Fal's `nano-banana-pro` model with a panorama reference image; writes a single JPEG and logs to `data/fal.json`.
- **`backend/requirements.txt`** — just `fal-client&gt;=0.8.0` (OpenAI/Cala calls go via raw `urllib.request`, no SDKs).
- **`backend/README.md`** — documents the `generate_story.py` flow only (anchor approval → run pipeline → outputs).

**No file today fetches people/places as first-class entities or builds anything encyclopedia-like.** `knowledge_search_events.py`'s `entities` field is the only existing touchpoint — it already asks Cala for `return_entities: True` and typed `entity_type`, which is a natural extension point for a new stage (e.g. a `generate_encyclopedia.py` that takes those entities, or issues further Cala `knowledge_search`/entity-lookup calls per person/place, then writes something like `frontend/data/esp-encyclopedia.json`).
